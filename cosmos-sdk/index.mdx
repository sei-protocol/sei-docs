<Danger>

**Deprecation notice**

Cosmos SDK and CosmWasm functionality is being deprecated in favor of EVM-only. For more details, see [SIP-3](https://github.com/sei-protocol/sips/blob/main/sips/sip-3.md) and [Proposal 99](https://seistream.app/proposals/99).

In addition, [Proposal 115](https://seistream.app/proposals/115) disables CosmWasm code uploads (`MsgStoreCode`) and contract instantiations (`MsgInstantiateContract`) chain-wide. No new CosmWasm contracts can be deployed. Only `execute` and `query` against pre-existing contracts remain available through the [CosmWasm precompile](/evm/precompiles/cosmwasm-precompiles/cosmwasm).

**IBC is now disabled in both directions.** [Proposal 116](https://seistream.app/proposals/116) and [Proposal 120](https://seistream.app/proposals/120) set the `ibc` module's `InboundEnabled` parameter to `false`, and [Proposal 121](https://seistream.app/proposals/121) set `OutboundEnabled` to `false` on July 31, 2026. No asset can be bridged into or out of Sei over IBC. IBC assets already on Sei can no longer be redeemed on their origin chain. See the [SIP-03 Migration Guide](/learn/sip-03-migration) for the full explanation and the list of affected assets.

</Danger>

## Tokenfactory is not supported

<Warning>

The tokenfactory module is removed as of the v6.8 upgrade. The module, its store, params, CLI commands (`seid tx tokenfactory ...` and `seid q tokenfactory ...`), gRPC/REST query and Msg services, and nearly all CosmWasm bindings are gone. Do not create, mint, administer, or build new integrations around tokenfactory denoms. Only the tokenfactory Msg types remain decodable so historical blocks still trace; any such message now fails validation (codespace `tokenfactory`, code 26, "tokenfactory module is deprecated") and is rejected without charging a fee. Existing `factory/` balances remain in the bank module and can no longer be minted, and denoms that previously carried a transfer allowlist now transfer freely, since the bank `factory/` denom transfer allowlist enforcement has been removed.

One exception survives the removal (#4549): the `burn_tokens` Wasm custom message still works, so a contract can burn a `factory/<contract>/<subdenom>` denom it created, from its own balance. The handler accepts only denoms the calling contract created (prefix `factory/<contract>/`) and burns from that contract's own balance; `mint_tokens` and every other tokenfactory Wasm message remain removed and unsupported. For new tokens, deploy an ERC-20 contract instead.

</Warning>
