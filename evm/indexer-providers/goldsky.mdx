## Goldsky

This guide explains the differences between Goldsky's products. It also shows how you can use them individually or together.

Goldsky has two main products, Subgraphs and Mirror. Both help developers work with on-chain data from Sei more efficiently. The two tools have similar goals: to retrieve, process, and query blockchain data. They differ significantly in how they handle data management, scalability, and customization.

If you are ready to start, see the [Goldsky quickstart guide for indexing Sei](https://docs.goldsky.com/chains/sei/?utm_source=sei&utm_medium=docs).

## How to choose between Subgraphs and Mirror

### Subgraphs: Structured, query-based data retrieval

**Overview:**

- Subgraphs support on-chain data from EVM-compatible chains only. On Sei, they support only Sei EVM.
- The data model is optimized for on-chain data. The entities and data types that you define in subgraphs are designed to represent blockchain data efficiently.
- You can create relationships and aggregations between on-chain entities. For example, you can track the balance of a user for specific tokens.
- You can enrich entity data with other on-chain sources through `eth_call`. However, you cannot integrate off-chain data.

**Examples:**

- Getting all transactions for a specific wallet address.
- Querying detailed event logs from a smart contract, such as token transfers or contract interactions.
- Building dashboards or analytics tools that query data periodically.

**Key advantages:**

- You can define custom data models that match your needs.
- Queries return results quickly because the data is pre-indexed.
- GraphQL gives you the flexibility to create custom queries for your application.

### Mirror: Real-time data streaming pipelines

**Overview:**

- The data model is flexible and accepts any type of data. You can combine blockchain data with your own data for more complex and customizable use cases.
- With Transforms, you can also process data before it is written to your database. You can pre-process it with a SQL dialect, and you can do external processing on your HTTP endpoint.

**Examples:**

- Streaming every block's data directly into a database for real-time analysis.
- Capturing real-time price updates or liquidity changes in DeFi protocols.
- Feeding live data into machine learning models for predictive analytics.

**Key advantages:**

- Mirror pushes data directly to your database as new events occur on-chain.
- Mirror scales to ingest data from multiple blockchain networks into a centralized database.
- Latency is minimal, so Mirror is ideal for use cases that need data to be available immediately.

### Decision guide: Subgraphs vs. Mirror

**Subgraphs**

- If you need to query specific Sei EVM data points or historical records, use Subgraphs.
- Subgraphs are best for applications that use only on-chain data and do not need off-chain sources.
- They are ideal for predefined data models, such as dApps that need to query specific smart contract events or run standard blockchain queries.
- They are a good fit for low-to-moderate traffic with relatively simple data structures and query needs.

**Mirror**

- Mirror is a better fit for applications that need both on-chain and off-chain data. You can combine data sources for advanced analytics or decision-making.
- It is ideal for multichain applications, because it makes data easier to manage across different blockchains without reindexing. This is especially true if your application needs non-EVM data, such as Sei Cosmos data.
- It suits high-traffic applications, where low latency and real-time data access are critical to performance and user experience.

**Example use case comparison:**

- **A DeFi analytics dashboard**: Use Subgraphs to get historical liquidity data and user interactions.
- **A real-time trading bot**: Use Mirror to stream price changes directly into your database, so that the bot can act instantly.

Select the tool that matches the data requirements of your project. Goldsky supports both structured, queryable data and real-time data streams. For more detail, read the [Goldsky comparison of Subgraphs and Mirror](https://docs.goldsky.com/subgraph-vs-mirror/?utm_source=sei&utm_medium=docs).

## Getting started

1. Sign up for an account at [https://app.goldsky.com/signup](https://app.goldsky.com/signup).
2. Install the Goldsky CLI:

   ```bash
   curl https://goldsky.com | sh
   ```

3. Go to your [Project Settings](https://app.goldsky.com/dashboard/settings) page and create an API key.
4. In the Goldsky CLI, run `goldsky login` to log in to your project, and then paste your API key.
5. After you log in, run `goldsky` to get started.

## Deploy a subgraph

You can deploy a subgraph on Goldsky in three main ways:

1. From source code
2. By migrating from The Graph or any other subgraph host
3. With instant, no-code subgraphs

To learn more about each way to deploy a subgraph, see [Deploying subgraphs](https://docs.goldsky.com/subgraphs/deploying-subgraphs/?utm_source=sei&utm_medium=docs) in the Goldsky docs.

## Deploy a pipeline

You can create a Goldsky Mirror pipeline in two ways:

1. **Flow**: Use the guided web experience in the dashboard.
2. **CLI**: Use the CLI interactively, or give it a pipeline configuration.

To learn more about how to deploy Mirror pipelines, see [Create a pipeline](https://docs.goldsky.com/mirror/create-a-pipeline/?utm_source=sei&utm_medium=docs) in the Goldsky docs.
