Verify your deployed contract with flattened source code, JSON input, Sourcify, or other methods. Verification makes your contract's source code public and verifiable. This creates transparency and trust.

## Benefits of verification

- Transparency: the source code is publicly available.
- Trust: the community can verify the contract's functionality.
- Security: verification gives greater confidence in the contract's integrity.

## Sourcify

[Sourcify](https://sourcify.dev/) is a decentralized, open-source service for contract verification. Sei has full Sourcify support on both Sei Mainnet (chain ID 1329) and Sei Testnet (chain ID 1328).

Sourcify verifies contracts byte by byte. It recompiles your source code with the exact same compiler settings and compares the output with the on-chain bytecode. You do not need an API key.

### Verify with Foundry

After you deploy your contract with Foundry, verify it on Sourcify:

```bash
forge verify-contract \
  --verifier sourcify \
  --chain-id <CHAIN_ID> \
  <DEPLOYED_CONTRACT_ADDRESS> \
  <PATH:CONTRACT_NAME>
```

**Sei Testnet example:**

```bash
forge verify-contract \
  --verifier sourcify \
  --chain-id 1328 \
  0x1234567890abcdef1234567890abcdef12345678 \
  src/Counter.sol:Counter
```

**Sei Mainnet example:**

```bash
forge verify-contract \
  --verifier sourcify \
  --chain-id 1329 \
  0x1234567890abcdef1234567890abcdef12345678 \
  src/Counter.sol:Counter
```

To check the verification status, run:

```bash
forge verify-check \
  --verifier sourcify \
  --chain-id 1328 \
  <VERIFICATION_JOB_ID>
```

You can also deploy and verify in a single step with `forge create`:

```bash
forge create src/Counter.sol:Counter \
  --rpc-url https://evm-rpc-testnet.sei-apis.com \
  --private-key $PRIVATE_KEY \
  --broadcast \
  --verify \
  --verifier sourcify \
  --chain-id 1328
```

<Info>To pass constructor arguments, add them after the contract path. For example: `forge create src/Token.sol:Token --broadcast --constructor-args "MyToken" "MTK" 18`</Info>

### Verify with Hardhat

The [`hardhat-verify`](https://hardhat.org/docs/learn-more/smart-contract-verification) plugin supports Sourcify by default. You do not need extra configuration or an API key.

#### 1. Install dependencies

```bash
npm install --save-dev hardhat @nomicfoundation/hardhat-verify
```

#### 2. Configure `hardhat.config.ts`

```ts
import { defineConfig, configVariable } from "hardhat/config";
import hardhatVerify from "@nomicfoundation/hardhat-verify";

export default defineConfig({
  networks: {
    sei_testnet: {
      type: "http",
      chainId: 1328,
      url: "https://evm-rpc-testnet.sei-apis.com",
      accounts: [configVariable("SEI_PRIVATE_KEY")],
    },
    sei_mainnet: {
      type: "http",
      chainId: 1329,
      url: "https://evm-rpc.sei-apis.com",
      accounts: [configVariable("SEI_PRIVATE_KEY")],
    },
  },

  solidity: {
    compilers: [
      {
        version: "0.8.28",
        settings: {
          optimizer: { enabled: true, runs: 200 },
        },
      },
    ],
  },

  plugins: [hardhatVerify],
});
```

<Info>`hardhat-verify` enables Sourcify verification by default. You do not need a `verify` config block for Sourcify.</Info>

#### 3. Deploy

```bash
npx hardhat ignition deploy ignition/modules/Counter.ts --network sei_testnet
```

#### 4. Verify with Sourcify

```bash
npx hardhat verify sourcify --network sei_testnet <CONTRACT_ADDRESS>
```

If your contract has constructor arguments, add them to the command:

```bash
npx hardhat verify sourcify --network sei_testnet <CONTRACT_ADDRESS> "arg1" "arg2"
```

If you run `npx hardhat verify` without a subtask, it tries to verify on all enabled providers (Etherscan, Blockscout, and Sourcify) at the same time.

### Verify via Sourcify UI

You can also verify contracts directly through the [Sourcify web interface](https://verify.sourcify.dev/):

1. Go to [verify.sourcify.dev](https://verify.sourcify.dev/)
2. Select **Sei** (chain ID 1329) or **Sei Testnet** (chain ID 1328)
3. Enter your contract address
4. Upload your source files or standard JSON input
5. Click **Verify**

### Setup and configuration

1. **Activate the plugin**: In Remix IDE, go to the **Plugin Manager** and activate the **Contract Verification** plugin.

2. **Configure network settings**:
   - Search for and select **Sei** as your blockchain
   - Choose your deployment environment:
     - **Testnet** (1328) for development
     - **Mainnet** (1329) for production

3. **Enable verification services**: Activate both verification methods:
   - **Sourcify**
   - **Etherscan**

4. **Configure Etherscan**: Set these values:
   - **API Key**: Get a key from [seiscan.io](https://seiscan.io)
   - **URL**: `https://seiscan.io`

### Deploy and verify

After you configure the plugin, deploy your contract through Remix as usual. When the deployment succeeds, the Contract Verification plugin verifies your contract automatically. It submits the contract to both Sourcify and Seiscan at the same time.

The plugin interface shows the verification status. Your verified contract is then publicly visible on the Seiscan explorer.

## Verify via 0xngmi Etherscan Verification (third‑party)

If a contract is already verified on another chain, you can batch-verify it with the community tool [Etherscan Verification by 0xngmi](https://etherscan-verification.0xngmi.com/). The tool copies the verified source from a "source chain" and submits it to [Seiscan](https://seiscan.io). This works only if the bytecode and compiler settings match.

<Warning>Prerequisite: The contract is already verified on at least one supported chain. That verified deployment must use the same compiler version, optimization runs, constructor arguments, and library addresses as the deployment on Sei.</Warning>

Steps:

1. Open [Etherscan Verification by 0xngmi](https://etherscan-verification.0xngmi.com/).
2. In **Source Contract**, paste the address of the contract that is already verified and select its chain.
3. In **Target Contracts**, add the address of your Sei deployment and select **Sei** as the target chain.
4. Click **Verify Contracts** and wait for the result.
5. Confirm the result on [Seiscan](https://seiscan.io). Open the contract page and check the **Contract** tab.

<Info>If verification fails with a bytecode mismatch, check the compiler version, optimization runs, constructor arguments, and linked library addresses again. They must be identical to the deployment on Sei.</Info>
