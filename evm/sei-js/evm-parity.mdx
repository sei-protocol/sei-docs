This matrix scores common EVM developer workflows on Sei once for each of three JavaScript libraries: viem, wagmi, and ethers. Each cell shows whether a maintained docs page or `@sei-js` template covers the workflow with that library. When a cell is not covered, its status shows who owns the gap: sei-js or the Sei network.

<Info>This page covers library workflows. For how the Sei network differs from Ethereum, method by method, see [EVM compatibility](/evm/evm-parity/evm-compatibility). For the scoring rules and the issue process, see the [EVM parity plan](/evm/sei-js/evm-parity-plan).</Info>

## Status legend

| Status | Meaning | Gap owner |
| --- | --- | --- |
| Verified | An automated check runs the workflow against Sei. | None |
| Covered | A maintained docs page or `@sei-js` template shows the workflow on Sei with this library. No automated check runs it yet. | None |
| Partial | A path exists, but the example, helper, or typing for this library is incomplete. | sei-js |
| Planned | No docs page, template, or helper covers the workflow for this library yet. | sei-js |
| Network-limited | Sei intentionally differs from Ethereum, so the workflow cannot behave as it does on Ethereum. | Sei network |
| Not core | The workflow is outside the core score. | None |

## Current score

Covered and Verified cells count toward the score. Network-limited and Not core cells are left out of it.

## Network differences

These differences come from the Sei network, not from sei-js. The workflows above still work, but they behave differently from Ethereum in the ways listed here.

| Affects | Sei behavior | Details |
| --- | --- | --- |
| Blocks and block tags | `latest`, `safe`, and `finalized` refer to the same block, because Sei has instant finality. | [Finality and block tags](/evm/evm-parity/finality) |
| Past logs and events | Public endpoints accept at most 2,000 blocks in one `eth_getLogs` request. A query that matches more than 10,000 logs fails instead of returning partial results. | [EVM compatibility](/evm/evm-parity/evm-compatibility#logs-filters-and-subscriptions) |
| Live blocks and events | Sei supports only the `newHeads` and `logs` subscriptions. The public WebSocket endpoints do not serve `eth_getLogs`. | [WebSocket connections](/evm/evm-parity/websocket) |
| Simulation and gas estimation | Governance sets the minimum gas price and can change the SSTORE cost. Sei does not burn the base fee. | [Gas and fees](/evm/evm-parity/gas-and-fees) |
| Message and typed-data signing | The wallet signs, so support depends on the connected wallet. | [Signing](/evm/evm-parity/signing) |
| Transaction signing | `eth_signTransaction` needs a key that the node holds, so it fails on public RPC endpoints. Sign in the client instead. | [JSON-RPC reference](/evm/reference) |

### Workflows outside the score

These workflows have the same status for viem, wagmi, and ethers.

| Workflow | Status | Details |
| --- | --- | --- |
| Storage proofs (`eth_getProof`) | Network-limited | Not supported since v6.7.0. Every call returns JSON-RPC error `-32000`. [See Proof verification.](/evm/evm-parity/evm-compatibility#proof-verification) |
| Blob transactions (EIP-4844) | Network-limited | Sei runs Pectra without blob transactions. [See Transaction types.](/evm/evm-parity/transaction-types) |
| Pending transactions and the pending block | Network-limited | The `pending` block tag returns the latest block. Sei does not support pending-transaction filters or subscriptions. [See Pending state.](/evm/evm-parity/evm-compatibility#pending-state) |
| ENS names | Not core | Sei does not run Ethereum Mainnet ENS. [See Name services.](/evm/evm-parity/evm-compatibility#name-services) |

## Report a gap

If a workflow behaves differently on Sei than this page says, or a workflow that you need is missing, open an issue with the [EVM compatibility template](https://github.com/sei-protocol/sei-js/issues/new?template=evm_compatibility.md). Maintainers classify each report, and no report should stay open longer than 14 days. For how reports are classified, see [How reports are handled](/evm/sei-js/evm-parity-plan#how-reports-are-handled).
