The [EVM parity matrix](/evm/sei-js/evm-parity) tracks how well common EVM workflows work on Sei with viem, wagmi, and ethers. This page explains what the matrix measures, how each cell is scored, and how compatibility reports are handled.

## Goals

- At least 95% of scored matrix cells are Covered or Verified.
- No open [`evm-compat` issue](https://github.com/sei-protocol/sei-js/issues?q=is%3Aissue%20is%3Aopen%20label%3Aevm-compat) is older than 14 days.
- Every gap is marked as a sei-js gap or as a Sei network difference, so it is clear who fixes it.

## Principles

- **Standard tooling first.** Use viem, wagmi, ethers, Foundry, Hardhat, and wallet standards as they are. sei-js adds a helper only when these tools cannot do a workflow on Sei by themselves.
- **Sei extensions second.** `@sei-js` packages fill the Sei-specific gaps: chain definitions, precompile ABIs, wallet discovery, log-range helpers, templates, and docs.
- **Evidence over claims.** Every Covered or Verified cell links to a docs page, a template, a test, or a conformance check.
- **Documented network differences.** When Sei differs from Ethereum on purpose, the docs explain the difference. sei-js does not hide it behind a wrapper.

## What the matrix measures

The matrix scores developer workflows, not package exports. A workflow is covered when you can find the Sei path for it, run it with your library, and understand any Sei-specific behavior.

The matrix groups workflows like this:

- **Connect and configure:** chain definitions, transports, wallet discovery, wallet connection, and chain switching
- **Read chain state:** balances, blocks, transactions, receipts, contract reads, and logs
- **Write and simulate:** transfers, contract writes, deployment, simulation, and gas estimation
- **Signing:** messages, typed data, and transactions
- **Tokens:** ERC-20, ERC-721, and ERC-1155
- **Sei extensions:** precompiles, pointer contracts, and address association

Each workflow gets one cell for viem, one for wagmi, and one for ethers.

## How cells are scored

| Status | A cell has this status when |
| --- | --- |
| Planned | No docs page, template, or helper covers the workflow for this library. |
| Partial | A path exists, but the example, helper, or typing for this library is incomplete. |
| Covered | A maintained docs page or `@sei-js` template shows the workflow on Sei with this library. |
| Verified | An automated check, such as a test in sei-js CI, runs the workflow against Sei. |
| Network-limited | Sei intentionally differs from Ethereum, and [EVM compatibility](/evm/evm-parity/evm-compatibility) documents the difference. |
| Not core | The workflow is useful in some ecosystems, but it is not part of the core EVM workflows on Sei. |

The score is the number of Covered and Verified cells, divided by the number of all cells except Network-limited and Not core cells. Network-limited and Not core cells stay in the matrix so that you can see the boundary, but they do not lower the score.

A cell changes status only when its evidence changes:

- It moves up when the evidence lands, for example a merged docs page, a published template, or a passing test.
- It moves down when the evidence breaks, for example when an example stops working or a test is removed.

## How reports are handled

To report a gap, open an issue with the [EVM compatibility template](https://github.com/sei-protocol/sei-js/issues/new?template=evm_compatibility.md). The template applies the `evm-compat` label.

Maintainers classify each report:

| Classification | Meaning | Outcome |
| --- | --- | --- |
| SDK gap | An `@sei-js` package, template, or docs page needs a change. | Maintainers fix it and update the matrix. |
| Network issue | The RPC response differs from documented Sei behavior. | Maintainers move the issue to [sei-chain](https://github.com/sei-protocol/sei-chain/issues). |
| Upstream issue | The behavior comes from viem, wagmi, ethers, or a wallet. | Maintainers link the upstream report and a workaround. |
| Docs issue | A docs page is wrong or missing. | Maintainers fix the docs. |
| Intentional divergence | Sei differs from Ethereum on purpose. | Maintainers make sure that [EVM compatibility](/evm/evm-parity/evm-compatibility) documents the difference, and mark the cell Network-limited. |

Maintainers classify a report within 2 days and assign an owner within 7 days. No report should stay open longer than 14 days. For the full triage and closure rules, see the [EVM compatibility SLA](https://github.com/sei-protocol/sei-js/blob/main/.github/EVM_COMPAT_SLA.md) in the sei-js repository.
